# Maintenance guide — SP-404 MK2 Simple Converter

Practical guide to keep this application running for years.

## 1. Project map (what touches what)

```
sp404_converter/
├── main.py            Entry point. Calls gui.main().
├── gui.py             PySide6 window + drag&drop + queue grouped by folder.
├── converter.py       EVERYTHING that talks to FFmpeg:
│                      │  - ffmpeg_bin()/ffprobe_bin() (bundled via sys._MEIPASS or PATH)
│                      │  - get_audio_info() (metadata via ffprobe)
│                      │  - is_compatible_format()/needs_conversion() (SP-404 rules)
│                      │  - compute_output_path() (paths + _sp.wav suffix)
│                      │  - convert_file() (copy if compatible, convert if not)
│                      │  - find_audio_files() (extension-based discovery)
├── styles.qss         Dark theme (editable without touching code).
├── build_exe.py       Portable recipe (PyInstaller one-file + bundled FFmpeg).
├── SP404Converter.spec  Generated by the build (ignored by git).
├── setup.py           pip install (creates the `sp404-converter` command).
├── start.bat          One-click setup + launch (creates .venv, installs, launches).
├── legacy/            Old UI (reference only; not maintained).
└── requirements.txt   Runtime dependencies.
```

**Golden rule:** the GUI (`gui.py`) never calls FFmpeg directly;
always through `converter.py` functions. Respect that and changes
won't break each other.

## 2. Suggested maintenance calendar

| When | Task | Where to look |
|---|---|---|
| Every 6–12 months | Update dependencies (`pip install -U ...`, see §3) | `requirements.txt` |
| Every 12 months | Test against the latest stable FFmpeg | https://ffmpeg.org/download.html |
| Every 12 months | Check the SP-404 specs haven't changed (Roland) | SP-404 MK2 manual |
| After every change | Run the suite (`python -m pytest tests -q`) | `tests/` + CI in `.github/workflows/` |
| After every change | Rebuild the exe and test it in a clean folder | `build_exe.py` |
| Always | Never commit `.venv/`, `build/`, `dist/`, `*.log`, `*.db` | Already covered by `.gitignore` |

## 3. Updating dependencies without breaking anything

1. Create a scratch venv and record what's installed: `pip freeze > before.txt`
2. Update in groups (never everything at once): first `PySide6`, then `ffmpeg-python`, then the rest.
3. After each group: run the tests and try the app (drop a folder → convert 1 compatible and 1 incompatible file).
4. If something breaks: go back to `requirements.txt` and pin the upper bound.
5. Only then update the ranges in `requirements.txt`.

**Historically sensitive spots:**
- **PySide6 6.x → 7.x (whenever it lands):** review drag&drop and GUI signals.
- **Python:** README asks for 3.10+. Before bumping minor versions,
  rebuild the exe: PyInstaller is version-sensitive.

## 4. FFmpeg (what breaks most often over the years)

- All coupling lives in `converter.py`. If ffprobe changes its `streams`
  format or ffmpeg renames a filter, only that file needs touching.
- **Lesson learned (2026):** ffprobe reports 24-bit WAVs with
  `sample_fmt: s32` (it decodes into a 32-bit container). That's why
  `get_audio_info()` prefers `bits_per_sample` when present, falling back
  to the `sample_fmt` heuristic. If you touch that function, the test
  `test_compatible_24bit_file_is_copied_not_reencoded` will tell you if the
  bug is back (24-bit files would get converted instead of copied).
- The app bundles FFmpeg **inside** the exe (conscious tradeoff:
  full portability for ~200 MB). `build_exe.py` warns when it can't find
  the binaries on PATH, and the exe comes out **non-portable**.

## 5. Rebuilding the portable exe

```powershell
python build_exe.py   # builds dist\SP404Converter.exe
```

- Requires FFmpeg on PATH (the build locates it with `shutil.which`).
- `icon.ico` is auto-detected; without it, the exe gets the default icon.
- Quick check: drop a folder with 1 compatible WAV (must be copied)
  and 1 MP3 (must become `*_sp.wav`).

## 6. Decided behaviors (not bugs)

- **Compatible = copy, not convert.** If it already meets the SP-404 spec
  (listed rate, 16/24-bit, mono or stereo, PCM), it's copied byte for byte.
- **The suffix is `_sp.wav`** and files already carrying it are skipped:
  a mirror folder is never re-converted.
- **MP3 in → WAV out.** Lossy formats are decoded to PCM so a second
  lossy generation never accumulates.
- **Stateless.** The app stores no settings or history; there is nothing
  to migrate or back up beyond the code (GitHub).

## 7. Tests

```
pip install -r requirements-dev.txt
python -m pytest tests -q
```

41 tests: spec table, binaries, ffmpeg command structure, ffprobe metadata,
per-rule compatibility detection, output paths, file discovery and
end-to-end conversion with on-the-fly generated tones (no audio fixtures
in the repo). Integration tests skip automatically when ffmpeg is not on
PATH. The GUI is not tested (manual verification instead).
